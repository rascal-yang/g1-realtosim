# 场景与物体建模自动路由

为用户完成可查看、可编辑、符合目标用途的场景或物体资产。由 Agent 负责拆解、选工具、调用、组装、检查和修正。沿用用户指定的工具与约束；普通技术选择自行完成，不逐物体要求用户选择 A/B。

## 先确定输入与交付目标

- **文字创作**：可以生成参考图，定义合理的尺寸和材质；标记为设计值或估计值。
- **实物重建**：以真实照片、视频和测量为约束；生成内容用于缺失区域补全，并保留来源。生成参考图不替代原始观测。
- **展示资产**：优先形状、材质、可编辑性和渲染表现。
- **仿真资产**：增加尺度、碰撞、物理属性和目标引擎检查。用于机器人数据采集时，阅读 [仿真交付要求](references/simulation.md)。

只有文字也能开始工作。缺少尺寸、隐藏面或物理参数时，先记录假设并继续可完成部分；仅在真实精度要求无法满足时提出具体补充数据需求。

## 最低还原要求：四项必须逐一交付与验收

无论选择哪条路线，场景还原至少覆盖以下四项。对任务范围内每个物体记录对应数据和检查结果；局部编辑沿用已有记录，只重新检查受影响项。不能只交付形状相似的网格并宣称还原完成。

| 必须还原的内容 | 资产中必须明确的信息 | 检查依据 |
|---|---|---|
| **大小与比例** | 米制长宽高、关键部件尺寸、最终缩放及尺度来源；房间、门窗和桌面也包含在内 | 对照实测尺寸或尺度锚点；在导出文件中复核包围盒。无尺度依据时记录绝对大小未校准，并检查可见比例 |
| **材质** | 部件对应的材料类别及渲染参数，如布料、塑料、金属、玻璃的粗糙度、金属度、透射等 | 在相近视角与光照下对照原图，并用另一种光照检查响应；仿真另按参考文档记录物理属性 |
| **纹理** | 颜色分区、图案、标签、织物/木纹等可见细节的位置、方向和尺寸；UV、贴图与必要的法线细节 | 对照真实可见表面，检查错位、拉伸、接缝和细节遗漏；背面补全标为推断，导出后检查贴图依赖 |
| **摆放位置与方位** | 统一场景坐标系中的平移、旋转、支撑对象，以及关键物体间距离和间隙 | 对照多视角或已标定视角下的布局、遮挡与接触关系；检查悬空、穿插、桌边距离和朝向 |

以真实输入还原时，优先采用测量、观测拟合和原始纹理，生成模型用于补足缺失信息。纯文字创作时四项同样必须明确，但按用户描述与设计约束验收，不声称还原了未提供的真实场景。

把每个物体的四项结果写入统一 manifest 或报告：目标/参考、最终值或资产引用、证据、检查方法、偏差/不确定范围和状态。状态区分通过、失败、未校准、未检查；没有真值时不编造误差。按用户精度要求和接触任务需要确定数值容差，未给定时记录本任务采用的工程目标及理由。

实物重建应保留原图与匹配相机视角的渲染对照；有额外视角时用于交叉检查。相机内外参有可靠依据后保持该依据，不能任意改相机去掩盖错误的物体尺度或布局。未通过项继续针对性修正，仍不满足时明确说明限制，不标记为完整还原。

## 检查可调用能力

先检查本地程序、权重、已有脚本、可用工具或接口及其实际输入输出。当前机器的复用线索见 [本机工具记录](references/local-tools.md)。不要从用户提及的模型名称推断接口已经存在；记录实际执行的模型、版本和提供方。

需要生成或编辑参考图片时，使用会话可用的图像生成工具，并遵循可用的 `imagegen` skill。外部图生 3D 可以是本地运行的模型，无须默认上传图片。新服务的费用、数据传输和凭据按已有授权处理，选择路由本身不需要额外确认。

## 按物体和部件路由

先列出场景物体、支撑关系、可动部件、接触区域和关键外观特征。对每个物体选择路线；允许同一物体的不同部件使用不同路线。

| 路线 | 优先采用的情况 | 重点检查 |
|---|---|---|
| A：Blender 程序化建模 | 房间、墙窗、桌柜、规则容器、重复结构、明确尺寸、机械装配件 | 尺寸、结构、倒角、连接方式、材质，避免只堆叠粗糙基本体 |
| B：图生 3D 后精修 | 玩偶、手办、有机形体、复杂雕塑或难以手工描述的外观 | 轮廓、背面、纹理身份、细长部件、孔洞；导入 Blender 后规范化 |
| 混合 | 玩具车、机器人摆件、复杂家具、带精密连接的外壳 | 生成外壳或有机部分；程序化补轮轴、关节、重复零件和接触结构 |
| 观测重建后补全 | 有足够真实多视角资料，且强调还原与尺寸精度 | 实测尺度、相机配准、观测一致性；遮挡补全标记为推断 |
| 复用已有资产 | 已有吻合且来源许可适用的资产 | 实际尺寸、拓扑、材料、部件和目标引擎兼容性 |

不要以细节数量或面数代替准确度。机械细节有明确结构时可以由程序化方式做得更好；图生 3D 不必承担整件资产。

例如：办公桌选 A；毛绒玩偶的外观选 B；玩具车选生成车身＋独立程序化车轮；机械角色选生成特色外壳＋程序化履带和转轴。最终选择取决于当前输入和检查结果。

用户要求 A/B 对比时，两条路线使用同一需求、尺度、评价视角及预算记录。普通建模任务只执行合适路线，不自动把所有对象都做两遍，也不把示例中的“五个场景”当作每次固定任务。

## 执行与组装

1. 建立独立任务目录，保留输入原件、脚本、配置和生成结果。此用户的独立资产任务默认放在 `~/code/zijian/asset_tasks/<日期>_<任务名>/`；已有任务沿用原目录。复用模型缓存，不覆盖原资产。
2. 写简短 `route_plan.json`：物体 ID、用途、输入来源、选择路线、理由、工具、四项最低还原要求的依据与目标、假设、失败回退方式。新反馈改变路线时更新记录。
3. 先定场景结构与物体包围盒，再处理关键物体。文字创作可先生成布局概念图，再为需要图生 3D 的对象准备独立参考图。
4. 对单物体图生 3D，优先无遮挡、完整轮廓、清晰部件、简单背景、适度透视的参考图；同一物体的不同视角保持身份一致。先核实模型支持单图还是多图，不能把多视图拼图随意塞给单图接口。
5. 保留生成原始结果，再修正漂浮碎片、退化面、朝向、比例和材质。修网格时保留手臂、把手、轮轴间隙等任务关键结构。可动零件单独组织。
6. 在 Blender 或目标场景工具中统一单位、坐标轴、命名、层级和材质，按支撑关系摆放。轴向变换只做一次，并以实际包围盒和渲染验证。
7. 出预览并实际查看：整体视角、侧后方、重点部件和用户最终视角。逐项完成大小、材质、纹理、摆放的对照检查；仿真任务在目标引擎中复核这四项，不能只凭 Blender 预览验收。
8. 针对发现的问题修正：纹理错位先修纹理，尺度错误先修尺度，生成几何持续不合格再换路线。避免每次从零生成整场景。

## 有限重试与质量判断

先用低成本预览确认路线，再做精修。遵守用户预算；未给预算时，每个需生成的对象默认最多 3 个生成候选（含初次）。每次重试改变一个有依据的因素并记录原因；耗时作业保留状态，支持续跑。达到候选上限后改用可行的混合/程序化方案，或明确交付限制，避免无界尝试。

四项最低还原要求始终适用；按任务目标增加以下检查：

- **形状与身份**：轮廓、比例、可见关键部件、背面完整性、部件是否粘连。
- **材质与贴图**：UV、贴图依赖、朝向、接缝、明显烘入的阴影或高光；必要时换光照检查。
- **场景**：尺寸、布局、支撑关系、穿插、用户关注的观察视角。
- **可用性**：实际打开导出文件，确认依赖可解析和主要组件保留；仿真检查使用对应参考文档。

实际验证失败时，报告局部失败和可用范围。不能用“生成完成”“有 USD 文件”或一张漂亮预览替代验收。

## 交付

按请求提供编辑源文件/构建脚本、可查看模型、预览和简短报告；仿真任务增加目标引擎资产及验证记录。报告说明每个对象选了什么路线、为什么、四项最低还原要求的逐项结果、哪些内容生成或估计、还存在哪些限制。

保留输入或提示词、可获得的随机种子、实际工具与模型版本、选中的候选、来源许可和参数依据。元数据可写入统一 manifest，不必为每条记录单独建文件。不声称未执行的调用、未做的真实测量或未运行的物理验证。
