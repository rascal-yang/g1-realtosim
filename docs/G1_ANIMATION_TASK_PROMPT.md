# 可复用任务准备提示词

复制下列内容交给Agent，并附任务描述和已知资产路径：

> 使用仓库 `g1_realtosim.animation_pipeline` 现有技能族准备新实验，复用脚本，不重写IK和导出器。
>
> 先判断是否属于“原办公室同一空篮，G1/Revo2，固定站位右手提把搬移放置”。属于时，以 `configs/basket_animation.example.json` 为模板，只改必要任务参数；否则列出缺少的资产/抓取/控制器/成功判据适配，并完成可独立验证的部分，不能强行套用篮子成功标签。
>
> 输入：任务意图=<填写>；初始物体状态=<填写或缺失>；目标=<填写或缺失>；资产与尺寸依据=<路径>；抓取先验=<来源或未知>。
>
> 对每个数值记录来源是观测、估计、人工指定或仿真真值；缺失值不要猜作真值。世界坐标Z向上，米、秒、弧度，四元数wxyz。当前篮子模板只支持原桌面、零初始偏航和根偏航pi/2；先验证配置限制。
>
> 输出新目录中的 motion_spec.json 和 task_reasoning.json：意图、技能族、左右手分工、物体相对抓点、接触阶段、关键时间、置信度/缺失信息、复用先验、改变参数和不选其他抓法的原因。
>
> 执行脚本生成、几何筛选和读回校验。失败则保存原因，提出有依据的配置修改，使用新目录；不要无限重试，不要改变质量/摩擦让失败消失。无须每条轨迹重新分析视频或调用VLM。
>
> 如果需要物理结果，执行 physical_commands.json 中现有命令，实际看初始双手和物体图像后记录审核。接触状态机自动执行；完整任务验收后才能标成功。动画位姿、物理状态、实际控制命令独立保存。没有运行的步骤标“未执行”。
>
> 报告新尝试的各阶段耗时、成功/失败、人工/Agent干预、碰撞覆盖、数据和视觉验收边界。若只跑了几何，physical_success=null，training_eligible=false。不要称原始关节参考已被直接跟踪，也不要称已实现实机迁移。
